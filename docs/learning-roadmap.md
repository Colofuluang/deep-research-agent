# 用 LangGraph 从零构建深度研究智能体

更新日期：2026-10-31。本文是本项目的教学主线，依据本地 HelloAgents 第十四章文档、配图和配套前后端源码制定。

## 最终交付与阶段边界

第一个完整版本对齐第十四章：用户输入主题，生成任务计划，逐个检索与总结，保存研究笔记，汇总带来源的报告，并通过 FastAPI 和前端展示进度。主流程由 LangGraph 负责。

第二个版本增加证据缺口检查、补充查询、预算控制与质量评估。这是对教程的扩展，不能仅凭有多个任务就认定实现了自主的多轮深度研究。

模型继续使用 DeepSeek；运行环境继续使用 aiagent-dev Conda 环境；代码保留在 LaCie 外接盘。先沿用当前目录，按实际需求增加文件。

## 教学方式

每节课按以下顺序进行：

1. 说明这节课在整个研究流程中的位置，以及要解决的具体问题。
2. 明确输入、输出、状态读写和验收条件。
3. 给最小示例或骨架，学习者完成核心逻辑；需要完整参考代码时可以直接给出并解释。
4. 先使用固定数据或模拟模型验证流程，再在需要时调用真实模型与搜索服务。
5. 验证一个正常场景和与本节相关的失败场景。
6. 学习者解释关键设计，并完成一个小修改，证明能够迁移使用。
7. 根据代码与运行结果记录完成情况，而不是根据“读过”或“没有抛异常”认定掌握。

外部搜索服务的异常单独排查；可以用固定的 SearchResult 数据继续学习图编排。模拟运行与真实研究必须明确区分。

## 教程职责到 LangGraph 的对应

| 教程设计 | 本项目设计 | 要掌握的内容 |
| --- | --- | --- |
| DeepResearchAgent 协调执行 | StateGraph、边和路由函数 | 流程由谁控制，何时结束 |
| SummaryState | ResearchState | 状态是执行数据，不等于自动送入模型的提示词 |
| TodoItem | ResearchTask + 任务执行记录 | 任务定义与执行状态分开理解 |
| PlanningService | plan 节点 | 结构化输出、验证与规划失败 |
| dispatch_search / SearchTool | search 节点调用 search_web | 外部服务适配、空结果与失败的区别 |
| prepare_research_context | 证据整理逻辑 | 去重、长度预算与来源对应关系 |
| SummarizationService | summarize 节点 | 依据证据总结、保留不确定性 |
| ReportingService | report 节点 | 整合任务成果、统一引用 |
| NoteTool | 阶段性文件读写；后续按需加入模型调用工具 | 研究笔记与模型自主工具调用的区别 |
| ToolAwareSimpleAgent / ToolCallTracker | 节点更新、模型消息与工具事件的记录 | 业务进度和模型文字流的区别 |
| 线程并发任务 | 后续使用 Send 与结果合并规则 | 并行状态冲突和结果排序 |
| FastAPI + Vue | 后续接入 FastAPI + Vue | 流式协议与图执行解耦 |

不要求为每个节点创建一个 Agent 类。模型决策使用模型调用；搜索、去重、保存等确定性操作使用普通函数。

## 分阶段课程

### 第 1 阶段：第一个 LangGraph 研究切片

目标：先使用固定数据理解 State、节点、边和 invoke，再连接已有规划、搜索、总结函数。

最终流程：START → plan → search_first_task → summarize_first_task → END。

涉及文件：models.py、state.py、nodes.py、graph.py、main.py。

验收：

- 能说明每个节点读取和返回哪些字段。
- 节点返回局部更新，不依赖到处修改同一个对象。
- 固定输入可以通过图得到一个任务总结；再做真实服务集成。
- 空搜索结果不能被标成已有充分证据的成功总结。

本阶段先使用默认覆盖式状态更新，实际需要累积时再引入 reducer。

### 第 2 阶段：全部任务与最终报告

目标：把原来 Python 中的任务循环表达为图中的条件路由。

流程：plan → search → summarize → record_task → 判断是否还有任务；有则返回 search，无则 report → END。

学习重点：task_index、条件边、终止条件、任务状态、共享状态与模型输入。

验收：

- 三个任务恰好执行三次，报告只在任务处理结束后生成。
- summary 与 task_id 一一对应；结果顺序可解释。
- 来源采用跨任务不冲突的稳定编号，例如 T1-S1；程序维护来源表。
- 失败或没有证据的任务在报告中有明确标记。
- 编号存在性可自动验证；来源是否支持发现仍需内容检查。

### 第 3 阶段：搜索适配、正文与证据

目标：对齐第十四章搜索调度和上下文整理能力。

主选项是教程支持的 Tavily；现有 SerpApi 实现作为已写好的适配练习保留。search_web 的返回契约保持稳定，更换服务不应重写图。

学习重点：服务原始字段到项目模型的转换、摘要与正文、去重、来源 ID、每来源和整体上下文预算。

验收：

- 同一 URL 去重后仍能追溯任务与证据。
- 搜索摘要不能冒充已读取的全文。
- 相对跳转链接保存为原始信息；进入全文读取时必须解析或明确标记无法读取。
- 超长正文有可解释的筛选或压缩策略。
- 接口返回成功不等于结果相关；使用固定问题检查相关性。

### 第 4 阶段：笔记、故障与恢复

目标：记录任务成果，并能恢复未完成的执行。

学习重点：run_id、task_id、文件保存、异常分类、checkpointer、thread_id、重复执行与幂等。

验收：

- 每次研究有独立输出目录，保存任务、来源、总结和报告。
- 普通 Markdown 笔记用于阅读与审计；图的 checkpoint 用于执行状态恢复，职责不同。
- 先用 InMemorySaver 理解 checkpoint，再用持久化后端验证进程重启后的恢复。
- 中断恢复不会重复追加来源或把未完成任务标为完成。
- 网络错误、认证失败、空结果、模型格式错误有不同处理方式。

运行时数据库路径到本阶段再确定；需要结合外接盘的实际文件系统能力验证。

### 第 5 阶段：流式进度与 Web 产品

目标：交付与第十四章相当的交互界面。

学习重点：先在终端观察节点更新，再加入文字增量；FastAPI 的 POST 流式端点；前端 fetch 流解析与 UI 状态。

验收：

- 有计划、任务开始、来源、总结、完成或失败、最终报告等明确事件。
- 从同一张图提供同步结果和流式进度，避免维护两套业务逻辑。
- 前端能展示任务状态、来源、总结与报告。
- 取消浏览器请求与真正停止后台工作分开验证。
- 如果渲染 Markdown，需实现相应依赖和内容处理，不能把纯文本展示声称为 Markdown 渲染。

### 第 6 阶段：并行处理

目标：理解并实现第十四章流式代码中的任务并发能力。

学习重点：Send、局部任务状态、reducer、并发限制、合并与稳定排序。

验收：

- 并行任务不覆盖彼此结果，报告收齐任务结果后再执行。
- 结果按任务 ID 归属，而非依赖网络完成顺序。
- 简单列表相加与按 ID 更新的区别得到实际验证。
- 用同一组固定数据比较串行和并行结果的一致性。

### 第 7 阶段：证据驱动的补充研究与评估

这是在教程完整流程之上的扩展。

流程：总结 → 检查缺口 → 预算内生成补充查询并再次检索；证据足够或预算耗尽后进入下一任务。

学习重点：结构化评审、条件边、每任务轮次、总调用预算、停止理由、评估。

验收：

- 补充查询明确对应一个证据缺口，而不是重复原查询。
- 即使模型持续建议继续，也会被代码预算终止。
- 预算耗尽时报告保留未知项，不编造填补。
- 使用固定问题集和失败场景，检查任务覆盖、证据支持、引用、调用次数与耗时。
- 区分结构验证、人工证据审查和模型辅助评审；单个总分不能替代证据核对。

## 紧接着做什么

可以先运行 `python examples/01_state_graph.py` 查看完整流程的固定数据预览。该示例不依赖 .env，也不发起外部请求。先观察输出中的节点名称、task_index 和 summaries；后续逐项实现真实研究节点。

下一节正式进入第 1 阶段，先把以下执行状态的含义写清楚：

| 字段 | 含义 | 最初由谁写入 |
| --- | --- | --- |
| topic | 当前研究主题 | 入口 |
| tasks | 规划得到的任务 | plan |
| task_index | 当前执行位置 | plan 初始化；任务记录后推进 |
| current_results | 当前子任务获得的资料 | search |
| current_summary | 当前子任务的初步总结 | summarize |
| task_results | 按任务 ID 保存的执行成果 | record_task |
| report | 最终报告 | report |

第一张单任务图只需要其中一部分字段；学到全任务循环时再添加其余字段。

先完成一次固定数据的状态流转，再接真实搜索。已有总结函数中的两处错误作为短练习修正：

```python
from .models import ResearchTask, SearchResult

for index, result in enumerate(results, start=1):
    ...
```

不要把这些状态字段全部塞给模型。每个节点只构造当前步骤所需的输入上下文。
