# 深度研究助手：研究工作台界面改版

日期：2026-11-03

状态：用户已选择「研究工作台」视觉方向，并于 2026-11-03 确认第一版范围，授权开始第一个教学切片。

## 目标与约束

将当前输入表单、日志列表和纯文本报告组成的页面，改为适合发起研究、观察进度和阅读长报告的工作台。继续使用 Vue 3、JavaScript、Vite 和已有 FastAPI/SSE 接口。

继续按教学方式实现：用户编写核心代码，导师解释新概念、检查实现并验证。分小切片改造，保留新建研究和按编号恢复的能力。

## 比较过的方向

- **研究工作台（用户已选择）**：报告占据主阅读区域，执行进度置于右侧。适合本项目的长报告和持续执行任务；窄屏时需要上下排列。
- **对话式研究**：问题、进度和报告集中在对话流中，更接近聊天；长报告与运行记录容易相互挤占阅读空间。本轮不采用。

## 第一版界面

### 顶部操作区

显示产品名称、当前主题与状态，提供「新研究」和「恢复研究」入口。研究编号作为次要信息显示；恢复编号输入区按需展开。

### 开始前

居中的研究主题输入区和一个主要操作按钮。提供少量可填入输入框的示例主题。布局和留白帮助用户聚焦问题，不堆叠指标卡片。

### 执行中与中断

主区域显示当前研究状态；右侧显示执行进度。详细运行日志可展开查看。错误时保留研究编号并突出「继续研究」操作。

使用真实事件更新界面，明确区分运行、完成和中断。现有进度数据以 message 和部分事件的 node 为主，不显示推测的完成百分比、剩余时间或来源数量。

### 研究完成

报告成为主区域内容，限制正文宽度，改善标题、段落、列表、代码块和参考文献的排版。将 Markdown 安全渲染为可读正文；生成内容中的 HTML 不直接信任。

保留报告已有的真实引用与参考文献。视觉稿中的独立来源卡片及引用原文预览属于后续增强：当前 completed 事件不包含完整来源列表，第一版不填入示例来源冒充研究结果。

## 视觉规则

使用清晰的字体层级、统一间距、轻边界和克制的绿色强调色，适配系统浅色/深色外观。以内容阅读为中心，避免大量装饰、强渐变和循环动画。

桌面采用主阅读区加右侧进度区；窄屏改为上下布局，输入框和按钮可换行，报告不横向溢出。保留输入标签、键盘焦点和请求期间的禁用状态。

## 实现边界与顺序

1. 整体布局、颜色、间距和开始前界面。
2. 运行、完成、中断与恢复的状态展示；复用现有 SSE 和请求逻辑。
3. 报告的 Markdown 渲染和阅读排版。

按需使用现有预留的 ResearchForm、TaskProgress、ReportView 组件，使 App.vue 继续负责状态和事件协调。组件拆分服务于清晰职责，不为形式增加层级。

本轮不增加研究历史管理、用户账号、多轮聊天、数据库任务列表或新的后端研究功能。独立来源预览待真实来源数据接口设计后另行接入。

## 验收

- 空主题、重复提交和编号格式检查继续有效。
- 新建研究可显示真实编号、持续进度、最终报告。
- 中断后保留恢复入口；输入旧编号后能够恢复对应研究，更新对应主题。
- HTTP 错误、SSE error 和意外断流都能显示明确状态并恢复操作能力。
- 桌面与窄屏可阅读、可操作，报告不横向溢出。
- 构建通过，检查模拟事件交互，再由用户执行真实浏览器端验收。

## 本次说明的边界

视觉稿用于确认布局和交互方向，其中的报告、进度和来源均为示例。选择视觉方向不代表示例里的所有数据或交互都已经由现有接口提供。
